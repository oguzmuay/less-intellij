# less-intellij

Monorepo with IntelliJ plugins that bring the LESS editor experience to IntelliJ IDEA.

- `less-ai-plugin`: brings the LESS editor's AI panel to IntelliJ IDEA: Claude, Codex, Gemini and Ollama sessions in terminal tabs, per-session status, and an agent-to-agent inbox.

Status: early development. See the plan in the repo history for scope.

- `less-middle-plugin`: replaces the empty editor screen with a LESS logo and a shortcut cheat sheet read from the active keymap.

- `less-monorepo-plugin`: detects the modules of a monorepo (Gradle, Maven, Spring Boot, sbt, Node with React/Next.js/Vue/Angular/Svelte/NestJS, React Native, Expo, iOS (Xcode/CocoaPods), Android, Python, Rust, Go, .NET, Swift, Dart/Flutter, Ruby, PHP, CMake) when the project opens and shows each module folder in the Project view with its own coloured icon and a short label (e.g. `Spring Boot · Gradle · Kotlin`). Icons are generated by `scripts/gen-monorepo-icons.py`.

## Install

Close IntelliJ, then run `scripts/install.sh` (builds all plugins, installs them and the LESS keymap). Needs IntelliJ IDEA 2026.3 installed; its bundled JBR is used as the JDK.

## Updates via GitHub

IntelliJ cannot tell where a manually installed plugin came from, so add a custom plugin repository once:
`Settings > Plugins > ⚙ > Manage Plugin Repositories > +` and enter
`https://github.com/oguzmuay/less-intellij/releases/latest/download/updatePlugins.xml` (the repo must be public).

The version lives in the `VERSION` file. To publish it, push a matching tag: `git tag release-$(cat VERSION) && git push origin release-$(cat VERSION)`.
Only `release-<version>` tags start the pipeline, and the tag must match `VERSION`.
GitHub Actions (`.github/workflows/release.yml`) builds all plugins with that version, creates the release and attaches the zips plus `updatePlugins.xml`. IntelliJ then offers the update.
